# System Security Plan: Hydro Plant Control and Dam Monitoring System (HPCDMS)

**Organization:** Cris Santos Company, LLC (owner and operator of the fictional Bramble Shoals Hydroelectric Project, Florida) | **Tier:** Micro | **Vertical:** Dams
**Outline:** NIST SP 800-18 Rev. 2, System Security Plan Outline Example (June 2026) | **Version:** 1.0, 2026-08-31
**Handling:** Contains control system details. Treat as CEII under POL-04; mark any copy given to FERC "Privileged - Security Sensitive Material" (FERC Security Program Rev. 3A 3.4.3.4). This sample is fictional.

## 1. System Name and Identifier
Hydro Plant Control and Dam Monitoring System (**HPCDMS**), identifier CSC-OT-001.

## 2. System Overview
The HPCDMS runs the Bramble Shoals Hydroelectric Project. It holds the headpond level by moving the 2 spillway gates, starts, loads, and stops the 2 generating units (4.4 MW total), collects readings from the dam safety instruments, and sounds the tailrace warning horn and strobes before releases. The plant is staffed 07:00 to 17:30 every day. Overnight it runs unattended: the gate PLC holds the level automatically, and the on-call operator-mechanic answers alarms and can view and operate the HMI remotely.

The company has 7 employees and no IT staff. An outside controls integrator built the system in 2015 and supports it remotely; an MSP runs the office IT; a SaaS monitoring service sends alarm callouts. This plan therefore says, for each control, what the company does itself and what it relies on a vendor for.

**Major components:**
- **SYS-01:** HMI PC in the control room (SCADA/HMI software) and the engineering laptop with PLC programming software
- **SYS-02:** spillway gate control (gate PLC, 2 local gate panels, position encoders, portable standby generator)
- **SYS-03:** unit control (2 unit PLCs, 2 digital governors, 2 static exciters, protective relays, local unit panels)
- **SYS-04:** dam safety instruments (headwater and tailwater levels, 4 uplift piezometers, 1 automated seepage weir, data logger) and the tailrace horn and strobes
- **SYS-05:** control network (switches, industrial firewall to the office network, the integrator's cellular router, the monitoring service's cellular data gateway)
- **SYS-06:** remote access paths (remote desktop tool on the HMI PC; integrator's always-on cellular VPN)

**FERC status.** The dam is in Security Group 3, so the FERC Security Program for Hydropower Projects (Rev. 3A) requires no security documents, but highly recommends a Security Assessment and Security Plan and says all groups "should consider having cyber security plans if they utilize cyber/SCADA assets" (3.3.3). Section 9 (cyber/SCADA) does not apply, because the plant is not interconnected to a Group 1 or 2 dam (9.1 note). The company ran the Section 9 screen voluntarily on 2026-07-16 (P03 rows G-023 and G-024) and uses the Table 9.3a baseline measures as its benchmark. This SSP is written to become the cyber section of the site security plan, answering the FERC engineer's recommendation at the 2025-11-04 inspection.

## 6. System Information Types and System Categorization
Information types were selected from NIST SP 800-60 Vol. 2 Rev. 1. Impact levels follow FIPS 199. The company raised integrity above the provisional level because of public safety at the tailrace.

| Information type | Confidentiality | Integrity | Availability | Rationale |
|---|---|---|---|---|
| Energy production (unit control, generation data) | Low | Moderate | Moderate | Wrong governor or unit commands could damage a unit; loss of generation costs about $2,750 a day and units can run locally (P05) |
| Water resource management and flood control (gate commands, headpond level) | Moderate | High | Moderate | An unauthorized gate opening sends a sudden flow change to the tailrace, canoe launch, and bank-fishing area, where recreation users could be swept away; local panels can take over within 30 minutes (P05 BP-01) |
| Disaster monitoring and emergency response (instrument readings, trigger points, tailrace horn) | Moderate | High | Moderate | False readings could hide a developing problem; the horn must sound before releases; the data logger keeps 60 days of readings |
| **HPCDMS category (high-water mark)** | **Moderate** | **High** | **Moderate** | |

**Baseline:** the NIST SP 800-53B **High** baseline, tailored for a 7-person company with one small control system and informed by the SP 800-82 Rev. 3 OT overlay. The plan documents **45 controls** that carry the FERC Table 9.3a baseline measures, the Part 12 duties that touch the system, and basic cyber hygiene (see `control-implementation.csv`). Every other High-baseline control is handled one of three ways:
- **Not relevant to these components:** many High-baseline controls assume general-purpose IT services the HPCDMS does not have (for example, public web content and mobile code). These are recorded as tailoring decisions in the OT inventory (POAM-007).
- **Tailored out for this tier:** controls written for organizations with security staff, such as separation of duties across administrator teams and program-level PM controls beyond PM-2.
- **Compensating controls for legacy devices:** the PLCs, governors, and exciters cannot enforce modern authentication. They are protected by network separation (SC-7), physical locks (PE-3), and limited remote access (AC-17), as SP 800-82 Rev. 3 and Rev. 3A 9.1.1.4 recommend.

## 11. Digital Identity Acceptance Statement
- **Control room (local):** operators sign in to the HMI with one shared account inside a locked control room. Single-factor local sign-in is accepted while the operator is physically present, but named accounts are required by POL-02 and planned with the HMI replacement.
- **Remote (on-call operators and the integrator):** today a shared password without MFA. This is **not acceptable** for a path that can open spillway gates. Required by 2026-11-30: one remote access path with named accounts, MFA, view-only by default, and a phone alert at every session start (POAM-002).
- **Office users:** sign in to the productivity suite with MFA; after the firewall rebuild they have no path into the control network.
