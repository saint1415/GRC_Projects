At the Micro tier the company keeps three core policies: access control (POL-02), incident response (POL-03), and data classification and handling (POL-04). A separate Information Security Policy would add little for a 7-person company with one plant, so its essential rules live in **POL-02 Part A. Program governance**:

| Essential rule | Where it lives | FERC or Part 12 basis |
|---|---|---|
| Security roles: FERC primary and alternate security contacts, security program coordinator, OT security lead | POL-02 A.1 | Rev. 3A 3.2 (bullets 5 to 8) |
| Annual risk assessment, which also serves as the Security Assessment | POL-02 A.2 | Rev. 3A 3.2 (bullet 1); 3.3.3 |
| Who may accept risk; gate risks never accepted at High | POL-02 A.3 | Rev. 3A 3.2 (bullet 1) |
| Discipline; good-faith reporting protected | POL-02 A.4 | Rev. 3A 3.2 |
| Vendor security terms and annual vendor review | POL-02 A.5 | Rev. 3A Table 9.3a coordination (voluntary benchmark) |
| Annual independent assessment | POL-02 A.6 | Rev. 3A 3.2 (bullet 1); results available for FERC review (bullet 12) |
| Retention of security records; 12.10 reports as permanent project records | POL-02 A.7 | 18 CFR 12.12(a)(1)(iii)(B) |
| Annual review of policies and the Section 9 screen each July | POL-02 A.8 | Rev. 3A Table 9.3a general measures (voluntary benchmark) |
| Exceptions process | POL-02 A.9 | Rev. 3A 3.2 |
| Security review of every change to the control system | POL-02 A.10 | Rev. 3A Table 9.3a system lifecycle (voluntary benchmark) |

Traceability for these rules is in `policy-control-map.csv` under POL-02. Revisit this choice if the company grows past the Micro tier (10 or more employees), acquires a second project, or if FERC moves the dam to Security Group 1 or 2, which would require a Security Plan with its own policy content (Rev. 3A 3.3.1, 3.3.2).
