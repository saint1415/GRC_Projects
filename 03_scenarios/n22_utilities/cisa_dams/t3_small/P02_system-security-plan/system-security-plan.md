# System Security Plan: Plant Control and Dam Monitoring System (PCDMS)

**Organization:** Cris Santos Company, LLC (licensee of the fictional Cypress Fork Hydroelectric Project, Florida) | **Tier:** Small | **Vertical:** Dams
**Outline:** NIST SP 800-18 Rev. 2, System Security Plan Outline Example (June 2026) | **Version:** 1.0, 2026-08-31
**Handling:** Contains control system details. Mark and handle as "Privileged - Security Sensitive Material" (FERC Security Program Rev. 3A 3.4.3.4) and as CEII under POL-04. This sample is fictional.

## 1. System Name and Identifier
Plant Control and Dam Monitoring System (**PCDMS**), identifier CSC-OT-001.

## 2. System Overview
The PCDMS runs the Cypress Fork Hydroelectric Project: it opens and closes the 4 spillway gates, starts, loads, and stops the 3 generating units (30 MW total), collects readings from 64 dam safety instruments and 2 upstream river gauges, and sounds the downstream warning sirens under the Emergency Action Plan (EAP). The control room is staffed 06:00 to 22:00 every day. Since March 2024, on-call operators monitor and control the plant remotely overnight.

**Major components:**
- **SYS-01:** SCADA and HMI (2 redundant SCADA servers, 3 operator HMIs, 1 engineering workstation)
- **SYS-02:** spillway gate control (gate PLC, 4 local gate panels, hoists, standby diesel generator)
- **SYS-03:** unit control (3 unit PLCs, 3 digital governors, 3 excitation systems)
- **SYS-04:** dam safety instrumentation, data acquisition, upstream gauges, and warning sirens
- **SYS-05:** OT network (control LAN, OT firewall, DMZ historian replica, OT historian, backup NAS)
- **SYS-06:** remote access paths (on-call operator VPN, vendor connections)

**Section 9 status.** Under the FERC Security Program for Hydropower Projects Rev. 3A, the PCDMS is subject to Section 9 and is designated **Critical**: a gate misoperation would exceed the Table 9.1c population-at-risk threshold, and the dam and powerhouse share one control network (P03 rows G-035 and G-036). This SSP is written to become the Cyber/SCADA annex of the FERC Security Plan (P03 row G-013).

## 6. System Information Types and System Categorization
Information types were selected from NIST SP 800-60 Vol. 2 Rev. 1. Impact levels follow FIPS 199. The company raised integrity and availability above the provisional levels because of the downstream safety consequence.

| Information type | Confidentiality | Integrity | Availability | Rationale |
|---|---|---|---|---|
| Energy production (unit control, generation data) | Moderate | High | Moderate | Wrong governor or unit commands can damage units (water hammer, overspeed); loss of generation costs about $38,000 a day (P05) but has safe manual workarounds |
| Water resource management and flood control (gate commands, reservoir levels) | Moderate | High | High | An unauthorized gate opening could release water toward a town of about 2,400 people; loss of gate control during a flood could overtop the dam |
| Disaster monitoring and emergency response (instrumentation, trigger points, sirens) | Moderate | High | High | False or missing readings could hide a developing failure mode; sirens must work when the EAP is activated |
| **PCDMS category (high-water mark)** | **Moderate** | **High** | **High** | |

**Baseline:** the NIST SP 800-53B **High** baseline, tailored for a 187-person company with one control system, and informed by the SP 800-82 Rev. 3 OT overlay. The plan documents **68 controls** that implement the FERC Section 9 baseline and enhanced measures and the most important High-baseline protections (see `control-implementation.csv`). Every other High-baseline control is handled as follows:
- **Inherited or not relevant for OT components:** many High-baseline controls assume general-purpose IT (for example, mobile code and session authenticity). Where the PCDMS uses no such technology, the control is recorded as a tailoring decision in the OT asset inventory (POAM-005).
- **Out of scope for this tier:** program-level PM controls beyond PM-2 and PM-9.
- **Compensating controls for legacy devices:** PLCs, governors, and exciters cannot enforce modern authentication. They are protected by segmentation (SC-7), physical protection (PE-3), and monitoring (SI-4), as SP 800-82 Rev. 3 and Rev. 3A section 9.1.1.4 recommend.

## 7. Authorization Boundary Description
- **Inside:** SYS-01 to SYS-06: SCADA and HMI, gate and unit controllers, instrumentation and sirens, the control LAN, OT firewall, DMZ, historian, backup NAS, and the OT VPN profile and vendor connection endpoints on the OT firewall. The control room, spillway, powerhouse, and instrument houses are the physical boundary.
- **Outside (interconnected):** the corporate network and identity provider (SYS-07, SYS-08), the cloud tenant historian replica and log workspace (SYS-10), the instrumentation SaaS (SYS-11), and the offtaker RTU link (SYS-13).

The diagram is in P04 `cloud-architecture.md`. The planned design moves all remote access to a DMZ jump host so no connection terminates directly on the control LAN.

## 11. Digital Identity Acceptance Statement
- **Control room (local):** operators sign in to the HMI with a username and password inside a badge-controlled room. Today this is one shared account; named accounts are required by POL-02 and planned in POAM-002. Single-factor local sign-in is accepted because physical access is controlled and the operator must be present.
- **Remote (on-call operators and vendors):** today password-only. This is **not acceptable** for a Critical Section 9 asset that can open spillway gates. Required: MFA (phishing-resistant authenticator) at the DMZ jump host, named accounts, and session recording (POAM-001).
- **Corporate users:** authenticate through the identity provider with MFA; they have no path into OT after the firewall rebuild.
